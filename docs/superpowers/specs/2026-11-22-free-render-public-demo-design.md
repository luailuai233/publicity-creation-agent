# 免费 Render 公开可用网站设计

## 目标与意图

把当前 Windows 本地项目改造成可由公开链接访问、能够处理访客真实输入的单实例面试展示站。任何拿到链接的访客都无需注册或密码即可走完素材、事实确认、案例分析、人工选择策略、正文生成、质检和导出全流程。站点用于作品展示，不作为长期保存真实业务数据的 SaaS。

## 已选方案

### 采用：Render 免费 Web Service + Docker + 临时 SQLite/文件目录

- 使用现有 FastAPI 模块化单体、SQLite、进程内 Agent Runner 和文件存储。
- Render 从 GitHub 仓库构建 Docker 镜像，容器监听平台提供的 `PORT`。
- 容器启动时先执行 Alembic，再启动单个 Uvicorn worker。
- `WORKBENCH_ROOT` 指向容器内可写的临时目录，数据库、上传和导出统一位于该目录。
- 实例休眠、重启或重新部署后允许数据丢失；访客仍可新建真实项目，也可点击“载入示例项目”重新载入标准脱敏样例。

### 未采用方案

- Render 付费持久磁盘：稳定性更好，但不符合零托管费用要求。
- 云服务器：可以持久化，但通常需要付费，并增加系统、HTTPS、防火墙和备份维护。
- PostgreSQL、对象存储和外部任务队列：适合多人正式产品，对单用户面试展示属于过度建设。

## 产品边界

### 必须实现

- 公开 URL 可打开，健康检查正常。
- 不设登录、访问密码或账号体系；任何拿到公开 URL 的人都可访问。
- 实例处于运行状态时，现有全部产品功能可用。
- 无密钥时使用确定性 Mock Provider，演示不依赖付费模型服务。
- 可选通过服务端环境变量切换 OpenAI-compatible Provider，密钥不进入页面或仓库。
- 首页可以新建真实项目；另保留可选的“载入示例项目”，用于快速体验，不把网站或真实结果标记为 Demo。
- 页面明确这是临时演示环境，不承诺长期保存访客数据。

### 不实现

- 注册、登录、权限、多人数据隔离和团队协作。
- 跨实例持久化、零停机、自动扩容和高可用。
- 自定义付费域名；使用 Render 提供的 `onrender.com` HTTPS 地址。
- 保证多个访客同时操作同一个 Demo。公开站仍是单用户语义，同时访问可能互相重置或修改演示数据。

## UI 调整

### 全局导航

- 项目页面必须始终提供七个工作区入口：我的桌面、活动文件、事实确认、灵感收藏、编辑提案、推文日志、发布检查。
- 不再只依赖当前可能不可见的左侧 Dock。项目页面顶部增加固定、可横向容纳七入口的工作流导航；当前入口、完成状态和待处理状态继续可见。
- 现有左侧 Dock 从项目页面移除，避免两套导航重复，并释放 1280 px 三栏页面宽度。
- 每个页面底部保留与当前步骤相关的主要操作。
- Agent 处于 `WAITING_USER / STRATEGY_SELECTION` 时，不显示通用文本回答框；改为明确说明“请选择一个创作策略”，并提供“前往编辑提案”按钮。
- 在编辑提案页选择策略后，按钮显示“已选择”，Agent 自动恢复；页面提供进入推文日志的明确入口。

### 顶栏文案

- 保留产品名“宣传编辑部电脑桌面”。
- 删除 `LOCAL · MOCK AI`。
- 删除“本地优先 · 自动保存”。
- 删除页面中的“Demo 模拟结果”、`DEMO WORKSTATION / LOCAL MODE`、首页“自动保存已开启”和编辑器底部“2 秒自动保存”等面向实现方式的宣传文案；保存机制继续工作，但不作为品牌文案展示。
- 顶栏空出的区域用于项目工作流导航；首页没有项目上下文时只显示产品名。

## 部署结构

```text
浏览器
  → Render HTTPS / onrender.com
  → 单个 Docker Web Service
      → FastAPI + Jinja2 + 静态资源
      → Agent Runner（进程内）
      → SQLite（临时目录）
      → 上传与导出（临时目录）
      → Mock Provider / 可选真实 Provider
```

## 真实模型与热点输入

- 配置 `AI_PROVIDER=openai_compatible`、`AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL` 后，案例分析、策略生成、标题大纲、正文、局部改写与质检均调用真实文本模型；配置 `AI_VISION_MODEL` 后，图片和案例截图调用视觉模型。
- 真实 Provider 的分析结果必须保存 `is_demo=False`；页面不显示模拟结果徽标。未配置模型时可继续使用 Mock Provider 做无费用体验，但这只是后端配置，不在页面顶栏宣传。
- 灵感收藏页提供真实录入表单，支持三种输入：粘贴文章正文、输入公开 HTTP/HTTPS 链接、上传 PNG/JPG/JPEG/WEBP 截图。
- 链接读取器从公开静态 HTML 中提取可读正文，过滤脚本、样式与页面噪声；若页面需要登录、验证码、JavaScript 渲染或存在反爬限制，保留原链接并提示改用粘贴正文或截图。
- 截图由服务端安全保存到当前项目目录；配置视觉模型时提取可见文字、场景和图片作用，未配置或低置信度时要求补充正文说明。参考案例内容始终与活动事实库隔离。
- 每个案例可选择“正文”“链接”或“截图”之一；需要同时提供图文时，用户可把文章正文作为一个案例、截图作为另一个案例，首版最多保留三个参考案例。

## 配置与启动

- Docker 基础镜像升级为项目支持的 Python 3.12。
- Docker 使用锁定依赖文件安装运行依赖。
- 新增 Render Blueprint 配置，声明免费 Web Service、健康检查 `/health`、Mock Provider 和临时工作目录。
- 启动命令使用 `${PORT:-8000}`，只启动一个 worker。
- `DATABASE_URL` 与应用运行目录必须指向同一个 SQLite 文件，避免迁移和应用连接不同数据库。
- `APP_ENV=production`，生产环境继续禁用故障注入接口。
- 不将 Playwright、测试缓存或本地 Windows 路径带入运行镜像。

## 安全与滥用边界

- 保留现有文件类型、单文件大小、项目文件总量和路径边界校验。
- 生产环境禁用故障注入。
- 增加基础安全响应头和请求体上限；不在日志记录上传正文、提示词或密钥。
- Demo 重置只删除 `is_demo=True` 项目及其边界内文件。
- README 明确不要上传真实敏感资料，公开站数据可能被其他访客看到或重置。
- 免费实例资源有限；保持单 worker、Agent 调用上限和有界重试，不加入耗资源的并行执行。

## 验证与验收

### 自动测试

- 顶栏测试确认被删除的三类文案不再出现。
- 导航测试确认所有项目页面都渲染七入口顶部导航，1280×800 与 1440×900 无横向溢出。
- Agent 页面测试确认策略选择等待态只显示前往编辑提案入口，不显示通用回答表单。
- Docker/Render 契约测试确认 Python 3.12、锁定依赖、动态端口、单 worker、健康检查和临时工作目录。
- 执行完整 `scripts/test.ps1 -q` 和 `scripts/e2e.ps1 -q`，要求零失败。

### 手工验收

1. 从 Render 公共 URL 打开首页，新建真实项目或载入示例项目。
2. 处理事实异常，启动 Agent。
3. Agent 暂停后通过可见导航进入编辑提案并选择策略。
4. 等待 Agent 生成正文，进入推文日志并执行发布检查。
5. 导出 Markdown，确认下载内容安全。
6. 等待或触发实例重启后重新打开；新建真实项目仍可使用，历史项目允许丢失，也可载入示例项目快速体验。

## 已知限制

- 免费 Render 服务会休眠，首次访问可能需要等待冷启动。
- 临时文件系统会在重启或部署时清空，上传、数据库和导出不长期保存。
- 多个公开访客共享单实例数据，可能互相影响；面试前应先打开站点并载入一次示例项目。
- 公开访客触发的真实模型调用会消耗部署者配置的 API 额度；部署者应设置模型服务侧预算、限额或限速，且不要把密钥提交到 Git。
- Render 平台状态、免费额度和休眠政策不由本项目控制。
