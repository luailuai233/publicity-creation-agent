# Agent Demo 双模式体验改版设计

日期：2026-11-15

## 1. 目标与背景

当前 Demo 已有可运行的 Agent、素材、事实、案例、策略、编辑、检查和导出能力，但界面没有把这些能力组织成易懂的演示路径：左侧导航除首页外被显式禁用，Agent 首页把内部六阶段做成静态卡片，任务参数只有目标可编辑，且“自主运行”与“逐模块演示”混在一起。

本次改版面向需要现场展示产品能力的用户。目标是让第一次打开的人能立即理解两种使用方式，并能实际运行每个模块，而不是只看静态页面。

## 2. 已确认的方向

采用“双模式”体验：

1. **自主创作**：填写目标、受众、语气、篇幅，一次启动 Agent 自动完成可执行步骤；遇到事实冲突或缺少参考时再请求用户确认。
2. **功能演示**：从素材开始，按事实、案例、策略、编辑、检查逐页运行；每页说明输入、可执行动作、输出与下一步。

右上角“所有数据保存在 D 盘”文案从界面删除，但所有源码与运行产物继续严格保存在 `D:\aipm\demo`。

## 3. 方案比较

### 方案 A：只保留一键 Agent

页面最简，但无法满足逐项展示每个模块功能的目标，不采用。

### 方案 B：只保留线性向导

演示清楚，但会弱化“这是一个自主 Agent”的核心价值，不采用。

### 方案 C：双模式（采用）

项目概览明确提供“自主创作”和“功能演示”两个入口，共用同一项目数据和底层服务。它同时满足自主性展示与分模块讲解，代价是需要明确状态同步和导航规则。

## 4. 信息架构

### 4.1 项目概览 / Agent 首页

首页不再展示六张静态阶段卡片，也不在 READY 状态显示无意义的暂停、恢复、取消按钮。

顶部任务区包含：

- 创作目标：多行输入；
- 受众：文本输入；
- 语气：文本输入，并可保留常用值；
- 篇幅：最少字数与最多字数两个数字输入；
- 主按钮“开始自主创作”；
- 次入口“进入功能演示”。

输入在启动前保存到 Project。校验规则：受众和语气非空；篇幅 200–10000 字；最小值不得大于最大值。启动 Agent 时使用刚保存的设置。

任务区下方改为简洁的状态摘要：

- READY：说明尚未启动，并给出两个入口；
- RUNNING/QUEUED：显示当前正在做什么、已完成步骤数和停止控制；
- WAITING_USER：只突出需要用户确认的问题与继续按钮；
- COMPLETED：显示完成摘要以及“查看策略”“编辑稿件”“审核并导出”；
- FAILED/PARTIAL：显示可理解的失败原因与重试入口。

暂停、恢复、取消只在对应状态下显示可用控件。

### 4.2 功能演示导航

左侧导航全部改为真实项目链接：

- 概览：`/project/{id}/agent`
- 素材与事实：`/project/{id}/materials`
- 案例方法：`/project/{id}/inspiration`
- 创作策略：`/project/{id}/strategy`
- 正文编辑：`/project/{id}/editor`
- 质量与导出：`/project/{id}/export`

导航不再使用 `href="#"`、`aria-disabled="true"` 或 `pointer-events:none`。当前页高亮由当前路由决定。尚未具备数据的页面仍可进入，但显示缺少什么和“前往准备”的链接，不展示死按钮。

每个导航项显示一个轻量状态：未开始、待确认、已完成。状态从真实数据库数据推导，不再把六个内部工具名当作首页卡片。

### 4.3 各模块的可运行演示

#### 素材与事实

- 上传真实文件或加载 Demo 素材；
- 显示解析状态、预览和提取出的事实；
- 可编辑/确认事实、解决冲突；
- 主动作“确认事实，进入案例方法”。

#### 案例方法

- 添加文本案例或使用 Demo 案例；
- 提供“分析案例”动作，实际调用现有参考分析服务；
- 展示可迁移方法与禁用表达，明确不写入活动事实；
- 主动作“生成创作策略”。

#### 创作策略

- 提供“生成/重新生成 3 个策略”动作；
- 展示推荐理由、使用事实和风险；
- 用户可选择策略，并保存语气/篇幅覆盖；
- 主动作“生成正文”。

#### 正文编辑

- 没有草稿时可点击“生成标题、大纲和正文”；
- 有草稿时可编辑并自动保存；
- 展示引用事实与来源；
- 主动作“运行质量检查”。

#### 质量与导出

- 提供“运行/重新运行质量检查”；
- 展示事实来源、冲突、隐私与表达问题；
- 事实阻断不得绕过；
- 通过后可导出 Markdown，并明确显示项目内导出结果。

所有逐页动作复用现有 Service/Agent Tool，不复制业务逻辑。

## 5. 操作流程

### 路线一：现场快速演示

加载 Demo 项目 → 项目概览 → 填写四项任务参数 → 开始自主创作 → 必要时回答确认问题 → 查看完成摘要 → 依次打开策略、正文、检查结果。

### 路线二：逐模块讲解

加载 Demo 项目 → 素材与事实（确认冲突）→ 案例方法（运行分析）→ 创作策略（生成并选择）→ 正文编辑（生成并修改）→ 质量与导出（检查并导出）。

两条路线共用同一项目状态。用户可以从一键路线切换到任何模块查看/覆盖，覆盖后下游结果变为待更新，并可重新运行 Agent。

两条路线遵守“同一时间只有一个写入者”：Agent 处于 `QUEUED/RUNNING` 时，所有模块页仍可查看，但手动修改和生成动作暂时锁定，并明确显示“Agent 正在运行”。终止、暂停或完成后恢复手动操作，避免页面操作与 Runner 竞争写入。

## 6. 数据与 API 调整

- 新增 Project 更新 Schema 与 `PATCH /api/projects/{project_id}`，保存目标、受众、语气和篇幅；
- Agent 启动表单先 PATCH Project，再创建 Run；
- 为案例分析、策略生成、正文生成和质量检查提供清晰的页面动作；优先复用现有 API，缺失时增加薄路由调用现有 Service；
- 页面导航状态由统一的 ProjectSnapshot/页面状态构建器产生；
- 操作失败在当前页面显示可理解的错误，不跳到空白页。
- 项目设置是受众、语气和篇幅的全局真源；策略页默认继承，只有用户显式覆盖时才保存策略级设置；
- 素材或参考资料的新增、编辑与删除递增 Project revision，并使受影响的策略、草稿和检查结果失效；
- 导航状态使用独立的展示模型从 ProjectSnapshot 和数据库结果推导，不依赖维护不完整的 `Project.status`；
- 策略重新生成只展示当前三条，已被历史草稿引用的旧策略保留为归档但不混入当前集合。

## 7. Demo 与页面行为细则

- Demo 重置后落到项目概览 `/project/{id}/agent`，由用户选择自主创作或功能演示；
- 事实冲突必须由用户显式选择，禁止脚本自动采用第一条候选事实；
- 案例方法页读取真实持久化 `ReferenceAnalysis`，并包含空、加载、失败、完成四种状态；
- 正文页把“大纲 + 正文”两次后端调用包装成一个用户动作，中间失败时保留已有结果并显示可重试原因；
- 正文自动保存同时覆盖标题和内容，不只保存正文；
- Agent 运行期间页面可读、修改动作锁定；锁定提示必须说明如何暂停或取消后再编辑。

## 8. 视觉原则

- 保留复古桌面识别度，但减少大面积边框、静态空窗和装饰卡片；
- 每页最多一个主按钮，其余是次级链接；
- 首页重点是任务输入和当前结果，不展示内部实现术语；
- 内部工具执行细节放进可折叠“运行记录”，默认只显示人能读懂的摘要；
- 桌面宽屏与 1280×800 下均能看到主动作，不横向溢出。

## 9. 非目标

- 本轮不接真实模型 API，继续使用明确标识的 Mock Provider；
- 不改写 Agent 核心状态机和六工具边界；
- 不增加多用户、权限、云同步或多实例队列；
- 不把演示页面做成仅播放动画的假流程。

## 10. 验收标准

- 右上角 D 盘提示文案不存在；
- 首页目标、受众、语气、最小/最大篇幅均可编辑并持久化；
- 左侧六个导航项全部可点击，URL 与当前项目一致，当前页正确高亮；
- Demo 重置后首先进入项目概览，不替用户预选路线；
- READY 页面没有无效暂停/恢复/取消按钮和六张静态阶段卡片；
- 自主创作可从首页完成到可查看结果；
- 逐模块路线的每页至少有一个实际调用后端并产生持久化结果的演示动作；
- 无前置数据时页面提供明确准备入口，不出现死链接或不可解释的禁用态；
- 修改上游数据后，下游状态正确失效；
- Agent 运行时模块结果可查看但手动写操作被锁定，结束后恢复；
- 冲突事实必须显式选择，案例分析展示真实持久化结果，编辑器可保存标题与正文；
- 原有事实/引用隔离、质量硬门禁、调用上限和 D 盘边界保持不变；
- 单元、集成、端到端测试覆盖两条路线和 1280×800、1440×900 两种视口。

## 11. 实施顺序

1. 项目设置更新 API 与表单；
2. 项目感知导航与状态构建器；
3. 首页状态摘要重构；
4. 补齐五个模块页面的实际动作与空状态；
5. 双路线端到端测试与视觉验证；
6. 更新 README 的演示脚本，说明用户只需加载 Demo 后选择一条路线。
